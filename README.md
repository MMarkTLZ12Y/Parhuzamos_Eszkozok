# Parallel Image Processing: OpenMP vs. OpenCL Performance Benchmark

This project was created as a university assignment. Its goal is to implement a parallelized grayscale image conversion algorithm and compare the performance of a shared-memory processor (OpenMP) and a heterogeneous graphics card (OpenCL) architecture across various image sizes and memory management strategies.

## 🚀 Features

- **CPU Parallelization (OpenMP):** Dynamic/static thread allocation across CPU cores.
- **GPU Parallelization (OpenCL - 1D):** Traditional, linear memory processing on the graphics card.
- **GPU Cache Optimization (OpenCL - 2D):** Memory management utilizing Spatial Locality, based on Work-group tiling, to maximize the utilization of the GPU L1/L2 cache.
- **Fair Benchmarking:** The measured GPU time includes the data transfer time (RAM -> VRAM and VRAM -> RAM) over the PCI Express bus.
- **Fully Automated Execution:** A single Batch file (`demo.bat`) handles compilation, a 5-round benchmark, exporting CSV data, and generating plots.

## 🛠️ Prerequisites

To run the project, the following software must be installed:
- **C/C++ Compiler:** GCC (MinGW with `mingw32-make` support on Windows).
- **OpenCL SDK:** Libraries appropriate for your graphics card (NVIDIA CUDA Toolkit, AMD APP SDK, or Intel OpenCL SDK).
- **Python 3.x:** For visualizing the measurements.
  - Required Python packages: `pip install pandas matplotlib`

## 🏃‍♂️ Usage and Execution

1. Place 7 images of different resolutions (ranging from a few tens of kilobytes to tens of megapixels) into the `data/samples/` folder, named `input1.jpg` through `input7.jpg`.
2. Open a command prompt in the project root directory.
3. Start the benchmark with the following command:
   ```cmd
   .\demo.bat
   ```

The script first compiles the program, then starts a 5-round benchmark. For maximum speed and consistency, physical images are only saved to the drive during the first round; the subsequent rounds purely measure computational and data transfer speeds.

## 📊 Results and Evaluation

At the end of the execution, the program generates plots visualizing the benchmark results in the `data/plots/` folder. 

Three curves can be observed on the plots:
- **Blue line (OpenMP):** CPU processing. Fastest for small-sized images, as there is no data transfer delay (overhead).
- **Red line (OpenCL 1D):** At gigantic resolutions, performance drops drastically—even falling below the CPU—due to slow PCIe data transfer and unoptimized memory striding (resulting in cache misses).
- **Green dashed line (OpenCL 2D):** The optimized GPU execution. Thanks to 2D data processing, the GPU cache hit rate is maximized, making this architecture the absolute fastest for high-resolution images, despite the significant data transfer overhead.
